# Social inbox

Inbox combines comments, replies, and quotes on posts that SimplePost published for a connected account. Use **All platforms** to filter the feed. **Needs reply** shows items that support replies and have no confirmed reply through SimplePost. **Reply and next** sends the text for the current item and moves focus to the next available reply. Actions use the receiving account. The feed shows the account name when a platform has multiple connections, and the reply composer always shows who will send the reply.

Select the refresh icon to check newer posts. The inbox **…** menu contains **Sync more**, which continues through additional posts and provider pages, and **Connections**, which shows sync status and permission errors. Each item has its own **…** menu with links to both posts and access to a sent reply. The feed keeps the last available results if a provider refresh fails. Provider access and history determine which items can be retrieved, and some providers return a limited view of nested replies.

### Provider permissions

- **Facebook Pages, Instagram, and Threads.** The additional Meta permissions are `pages_read_engagement`, `pages_read_user_content`, and `pages_manage_engagement` for Pages, `instagram_business_manage_comments` for Instagram professional accounts, and `threads_read_replies` for Threads. The Threads connection already requests `threads_manage_replies` for writing. If Meta requires app review or Advanced Access for the app and account, complete it before asking users to reconnect. The Instagram comment-management and Threads reply APIs offer reading and replies. The published APIs used here have no write operation for liking those comments or replies. [Meta permissions](https://developers.facebook.com/docs/permissions) · [Facebook comment likes](https://developers.facebook.com/docs/graph-api/reference/comment/likes/)
- **YouTube.** Reconnect with `youtube.force-ssl` to use the documented comment and reply operations. Comment resources expose a `likeCount` field and have no API method for liking the comment. The separate rating endpoint applies to videos. [Comment methods](https://developers.google.com/youtube/v3/docs/comments) · [Reply authorization](https://developers.google.com/youtube/v3/docs/comments/insert) · [Video ratings](https://developers.google.com/youtube/v3/docs/videos/rate)
- **LinkedIn.** Apply for the appropriate LinkedIn Community Management permissions for the SimplePost app. Member comment reads need the restricted `r_member_social_feed` grant, which LinkedIn gives to select developers. Comment replies and reactions use `w_member_social_feed`. Organization access has its own scopes and Page-role requirements. Reconnect the account after LinkedIn grants the respective permissions. [LinkedIn comments and scopes](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/comments-api) · [LinkedIn comment reactions](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/reactions-api)
- **X.** Request `like.write` on reconnect to enable likes. Quote and conversation reads also depend on the X app’s access and usage limits. [X likes](https://docs.x.com/x-api/users/like-post) · [X quotes](https://docs.x.com/x-api/posts/get-quoted-posts)

### Setting up a dev account

Register the Scheduler's HTTPS callback for each provider, using `/api/connect/callback/{platform}` on the dev origin. Connect the publishing account first. After granting the user inbox access, open **Reconnect** on the account warning in **Inbox** for that same account.

### Platforms that need a different integration

- **Forem.** The current adapter reads comments. Forem documents authenticated comment reactions, so likes are possible where an instance exposes the operation. The write requires a numeric comment ID, while the documented comment read response exposes `id_code`. SimplePost would need a supported way to resolve the write target. The public API reference lists comment reads and reaction writes and offers no comment-creation method. [Forem API](https://developers.forem.com/api/v1)
- **Telegram.** Channel comments are messages in a linked discussion group. A bot with the appropriate group access can collect new updates, reply, and set supported message reactions. That would require a discussion-group connection and update ingestion with native message mapping. Bot updates are retained for at most 24 hours and the Bot API offers no inbox history backfill. [Telegram Bot API](https://core.telegram.org/bots/api)
- **TikTok.** The Display API for an authorized user provides profile and video metadata. TikTok offers public comment reads to eligible non-commercial researchers through a separate Research API. That access does not provide a commercial creator inbox or reply and like writes. [TikTok Display API](https://developers.tiktok.com/doc/display-api-overview/) · [Research eligibility](https://developers.tiktok.com/products/research-api/) · [Research comment reads](https://developers.tiktok.com/doc/research-api-specs-query-video-comments/)
- **Pinterest.** The published v5 API supports operations on Pins, boards, and analytics. Its public specification has no Pin comment, reply, or like operations for this inbox. Extra publishing permissions do not add those operations. [Pinterest v5 API specification](https://github.com/pinterest/api-description/blob/main/v5/openapi.yaml)

## Private rollout

Deploy the additive Prisma migration using the normal scheduler release process. Individual `SOCIAL_INBOX` grants in `UserFeature` control access to the page, API, MCP discovery and execution, and provider refresh. The migration creates zero grants. After deploying the scheduler, use the [existing administrative grant pattern](../image-fitting.md#private-hosted-rollout) with `Feature.SOCIAL_INBOX` and the verified internal user ID. Remove the row to revoke access.

`POST_ANALYTICS` and `SOCIAL_INBOX` are independent grants. Social account connections and reconnects start with publishing scopes and add the scopes for the user's grants and the selected platform. A user with both grants can consent to both sets in one flow. Existing connections gain permissions when their owners reconnect and consent.

For Inbox, the default platforms are Facebook, Instagram, Threads, YouTube, and X. X requests `like.read` to check the connected user’s recent likes and `like.write` to like a reply. Conversation search can also find replies that the connected user sent directly on X. Bluesky already authorizes replies and likes through its existing connection. Set `SOCIAL_INBOX_OAUTH_PLATFORMS` to override the platform list, or set it to an empty value to disable additional Inbox requests. TikTok's pilot scopes cover [analytics](../post-analytics/platform-permissions.md).

Inbox checks for recent activity while it is open. Use **Refresh inbox** to check again or **Check older posts** to continue the scan. Open a comment on its platform or use **Preview original post** to see what the person replied to. A reconnect must return the same account. During provider review, the tester needs an account that can authorize the new scopes on that developer app.

## SDK and clients

- The TypeScript SDK exposes `listSocialPostComments`, `listSocialPostQuotes`, `replyToSocialComment`, `likeSocialItem`, and `getSocialActivityCapabilities`. It takes provider-native references and caller-managed credentials.
- The scheduler API serves `GET /api/v1/social/inbox`, `POST /api/v1/social/inbox/refresh`, `POST /api/v1/social/items/{id}/reply`, and `PUT /api/v1/social/items/{id}/like`. The hosted clients use the opaque IDs from the feed. Filters include `platform`, `accountId`, `kind`, and `needsReply`.
- Run `simplepost inbox refresh --reset` and `simplepost inbox list --platform bluesky --json` from a connected CLI. Use `simplepost inbox like ITEM` or `simplepost inbox reply ITEM --text "Thanks!" --idempotency-key KEY`. For another page of cached items, use `--cursor` with the returned cursor. Run another refresh without `--reset` to continue the sync.
- MCP exposes `list_inbox_items`, `refresh_inbox`, `reply_to_inbox_item`, and `like_inbox_item`. Listing requires `posts:read`. Refresh and mutations require `posts:write`.

Reuse the exact reply key and text after an interrupted request. A receipt can be pending, sent, failed, or uncertain. If delivery is uncertain, check the native platform before sending another reply.
