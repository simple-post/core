Use a consistent taxonomy such as `utm_source=chatgpt&utm_medium=plugin&utm_campaign=directory&utm_content=listing_website` (and `plugin_setup`, `plugin_help`, `profile_bio`, etc. by placement). Use stable lowercase values without identities, emails or tokens. Inventory uneditable/native authorization paths separately; do not append campaigns to OAuth redirect URIs, signed state, Stripe returns or arbitrary assistant responses.
2. **Check listing-side analytics where the platform exposes them.** Collect impressions, listing views, installs/connects and feature placements with dates, separately from website metrics. Record September 3 as the user-confirmed launch. Keep the September 4–9 featuring explanation as a hypothesis unless platform evidence confirms it. Do not infer installs from website outbound clicks or infer referral from later client use.
3. **Configure Plausible goals and properties.** Keep existing goals; add Sign In Viewed, Sign In Code Sent/Resent/Failed, Assistant Install Click, First Tool Called/Succeeded, First Post Attempted, Second Publishing Day, Plan Viewed and AI Authorization Cancelled as needed. Verify existing Signup Completed, AI Integration Connected, Social Account Connected, First Post Created/Scheduled/Published and paid goals. Enable relevant breakdown properties (method/reason/client/platform/plan/landing_page/landing_category/section) if the account's plan supports them. Keep marketing and app paths distinguishable. Account cohort conversion comes from the database, not a Plausible same-session funnel.
4. **Verify the analytics proxy.** Preserve a real visitor's forwarding behavior; test a normal browser and a deliberately dropped test request. Check CORS allows the owned app origin. Do not weaken the existing CSP or permit unrelated origins. The proxy remains external configuration.
5. **Review Stripe webhook subscriptions.** Confirm the deployed, signature-verified live endpoint receives the existing subscription and invoice events plus `checkout.session.expired`, `invoice.paid`, `invoice.payment_failed` and `invoice.payment_action_required`; verify `checkout.session.completed`, `invoice.payment_succeeded`, and `customer.subscription.created/updated/deleted` remain covered. Do not add a second endpoint that duplicates business synchronization. Confirm delivery/retry health. Keep test-mode facts out of live paid totals; never replay a historical event just to make a current conversion chart increase.
6. **Configure SigNoz dashboards and alerts.** Add capture-failure alerts for `errorCode=funnel_capture_failed`, database optional post-failure-measurement warnings, webhook failures/retry backlog . Build breakdowns for tool failures, social connection errors, post rejection/publishing errors and billing denials, alongside traffic and signup volumes. Alert on a sustained failure ratio with a minimum volume; low traffic alone should not imply an outage. Use existing sanitized app logs for detailed operational diagnosis rather than sending raw exceptions to analytics.
7. **Choose data retention and access.** Propose a bounded retention period for the account-linked operational event ledger (for example, 13 months), with restricted operator access. Validate volume and analysis needs before configuring cleanup. Milestones, first-payment evidence and account deletion rules must be preserved. No cleanup or retention deletion runs in this PR.
8. **Mark internal/reviewer accounts.** Review the actual account IDs privately and set the server-owned exclusion flag for staff, load tests, demos and reviewers. Existing admins/new demo accounts are handled by code; historical non-admin internal accounts need an explicit inventory. Do not use an email-domain heuristic that could exclude real customers.
9. **Record exact release and campaign timestamps.** Add analytics annotations and a release log for the signup/activation changes, plugin ranking/listing edits, trial-offer changes and the deployment of these measurements. The single measurement version marks instrumentation coverage; historical product changes are compared using verified release dates. Compare matched signup cohorts at the same age and trial length; wait until the chosen windows mature. Keep concurrent acquisition and product changes separate when drawing causal conclusions.
10. **Review analytics/cookie documentation.** Confirm the disclosed first-party attribution retention and internal product measurement cover the added latest-touch cookie and event ledger. Any required policy or consent-flow changes need separate review; no banner, policy text or customer-facing consent change is included here. Existing browser analytics opt-out remains respected.

11. **Reconcile historical payments separately.** For September comparisons predating acquisition tracking, use the earlier analysis or a complete verified historical invoice export joined to known accounts. A renewal alone cannot establish the first payment. Plan any historical import separately with explicit coverage and idempotency; do not replay browser conversions or assign guessed acquisition/version labels. New tool/attempt/repeat milestone and event coverage is prospective.

The largest unresolved attribution gap is referrer-less, untagged traffic and assistant-native/cross-device signup. Editable tagged links and platform-side evidence improve this; these PRs do not invent a source for the remainder.
